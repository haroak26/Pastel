# Latte Product Strategy: The Customer Platform

## The Problem with Everyone Else

| Platform | What they do | What they're missing |
|----------|-------------|---------------------|
| **Intercom** | Chatbot + inbox + basic articles | No roadmap, no changelog, no product feedback loop |
| **Zendesk** | Enterprise ticketing | Bloated, 90s UX, no product tools |
| **Front** | Shared inbox (email-only) | No tickets, no AI, no product hub |
| **Linear** | Project management | No customer facing, no support |
| **Gleap/Canny** | Feature request boards | Just feedback, no full loop |

Customers end up using **4-5 tools** to do what should be one workflow: support → feedback → roadmap → ship → notify.

## What Makes Us Genuinely New

### 1. Support + Product in one place

No other tool connects tickets to a roadmap to a changelog. When a customer says "I want dark mode," that feedback flows:

```
Customer says "I want X" via email/chat
  → Lands in unified inbox
  → AI detects it's a feature request
  → Customer gets link to upvote on public board
  → Team reviews, promotes to roadmap
  → Task created and assigned
  → Work completed
  → Changelog auto-generated
  → Upvoters notified: "It shipped!"
```

All in one platform. No data silos, no manual copy-paste between tools.

### 2. Product Hub is the hero feature

- **Feature Requests** — public board with upvotes, linked to conversations
- **Roadmap** — drag-and-drop timeline, public/private visibility per item
- **Changelog** — auto-generated from completed tasks, notify upvoters on publish

This is the billboard moment. Linear + Gleap built in.

### 3. Unified inbox, not a chatbot

Every channel (email, chat, messenger) lands in one clean inbox. No "bot first" nonsense unless you want it. Front-level simplicity but with ticket mode when you need SLAs.

### 4. Auto-changelog

Complete a Linear-style task → changelog entry auto-drafts. Publish it → upvoters get notified. "It just works" magic.
