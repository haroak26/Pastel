# Forms Component Law

> Defines the canonical design rules for all form components generated by Picasso. Every input, selector, toggle, and form layout must follow these rules exactly. Deviations constitute design defects.

---

## 1. Input Field Design

### 1.1 Label Placement

Labels MUST be placed **above** the input field. This is the only acceptable placement for accessibility and scannability.

```
CORRECT:
┌─────────────────────────────┐
│  Email Address           *  │  ← label above (14px, font-medium)
│  ┌─────────────────────────┐│
│  │ name@example.com        ││  ← input
│  └─────────────────────────┘│
│  We'll never share your     │  ← helper text (12px, text-muted)
│  email with anyone.         │
└─────────────────────────────┘

WRONG:
┌─────────────────────────────┐
│  Email Address: [name@ex..] │  ← NEVER inline label
└─────────────────────────────┘
```

Rules:
- Label font size: 14px (text-sm equivalent)
- Label weight: font-medium (500)
- Required indicator: red asterisk `*` appended with 2px gap
- Gap between label and input: 6px

### 1.2 Input Dimensions

| Context          | Height  | Font Size | Padding X |
| ---------------- | ------- | --------- | --------- |
| Default          | 40px    | 14px      | 12px      |
| Large (forms)    | 48px    | 14px      | 16px      |
| Compact (tables) | 32px    | 12px      | 8px       |
| Dense (inline)   | 28px    | 12px      | 8px       |

Default height for standalone forms is 40-48px. Never use input heights under 28px.

### 1.3 Placeholder Text Rules

Placeholders are **examples**, not labels. They must NEVER replace a label.

```
CORRECT:
Label: "Company website"
Placeholder: "https://example.com"
→ User sees the label AND a helpful format hint.

WRONG:
No label, placeholder: "Company website"
→ Label disappears when user starts typing — inaccessible.
```

Do's and Don'ts:
- DO use placeholders to show expected format (`"MM/DD/YYYY"`, `"example@domain.com"`)
- DO use placeholders for optional hints (`"Add a brief note..."`)
- DO NOT use placeholders as the only label
- DO NOT use placeholder text that repeats the label verbatim
- DO NOT use placeholder text that disappears and leaves the user guessing

### 1.4 Helper Text Position

Positioned **below** the input, with a 4px gap from the input border:

```
┌─────────────────────────────┐
│  Password                   │
│  ┌─────────────────────────┐│
│  │ ●●●●●●●●●●              ││
│  └─────────────────────────┘│
│  Must be at least 8          │  ← helper (12px, text-muted)
│  characters.                 │
└─────────────────────────────┘
```

- Font size: 12px (text-xs equivalent)
- Color: neutral-400 (muted)
- Max width: matches input width
- Must wrap naturally if needed

### 1.5 Character Count Display

Positioned **right-aligned** on the same line as helper text when both exist, or alone below the input:

```
┌─────────────────────────────┐
│  Bio                        │
│  ┌─────────────────────────┐│
│  │ Hello! I'm a designer.. ││
│  └─────────────────────────┘│
│  Brief introduction    24/150│  ← helper left, count right
└─────────────────────────────┘
```

- Font size: 12px
- Color: text-muted normally, shifts to danger-500 when approaching limit (<10 chars remaining)
- Format: `{current}/{max}` (e.g., `24/150`)

## 2. Input States

Every input supports these 6 visual states. Transitions between states use 150ms ease.

### 2.1 Default State

```
Border: 1px solid neutral-200
Background: white
Border radius: rounded-md (8px)
Text color: text-primary
Caret color: accent-500
```

### 2.2 Hover State

```
Border: 1px solid neutral-300
Background: white
Cursor: text (I-beam)
Transition: border-color 150ms ease
```

### 2.3 Focus State

```
Border: 1px solid accent-500
Box-shadow: 0 0 0 2px accent-500/25 (ring-2, offset-2px)
Outline: none (ring replaces default outline)
Z-index: elevated by 1 to clear adjacent borders
```

Critical rule: when focus enters, do NOT change background color. Only border and ring change.

### 2.4 Filled / Dirty State

```
NO visual change from default state.
Do NOT add a checkmark icon.
Do NOT change border color to green/success.
The only indicator of a filled value is the text content itself.
```

### 2.5 Error State

```
Border: 1px solid danger-500
Background: danger-50 (#fef2f2 equivalent)
Box-shadow: none (error and focus are mutually exclusive; error wins)
```

When an input has an error AND receives focus:
- Keep the error border (danger-500)
- Add focus ring in danger-500/25:
  ```
  Border: 1px solid danger-500
  Box-shadow: 0 0 0 2px danger-500/25
  ```

### 2.6 Disabled State

```
Opacity: 0.5 (entire element)
Pointer events: none
User select: none
Background: neutral-50 (subtle gray)
Cursor: not-allowed (on hover region)
```

Never remove the text content on disable — the user must still be able to read disabled values.

### 2.7 Read-Only State

```
Background: neutral-100
Border: 1px solid neutral-200
Cursor: default (no text cursor)
Focus ring: suppressed (read-only inputs should NOT get a focus ring)
Text color: text-primary (full contrast — user must read this)
```

Read-only is NOT the same as disabled. Read-only means "you can see this but it comes from somewhere else." Disabled means "this field does not apply."

## 3. Error Message Format

### 3.1 Visual Specification

```
┌─────────────────────────────┐
│  Email Address              │
│  ┌─────────────────────────┐│
│  │ not-an-email            ││  ← danger-500 border, danger-50 bg
│  └─────────────────────────┘│
│  Please enter a valid        │  ← 14px, danger-500, 4px gap
│  email address.              │     below input
└─────────────────────────────┘
```

Specs:
- Font size: 14px
- Font weight: 400 (normal)
- Color: danger-500 (#ef4444 equivalent)
- Gap from input bottom: 4px
- Icon: optional danger icon (16px, inline with text) — include only for critical errors

### 3.2 Message Content Rules

| Bad Message                                  | Good Message                                             |
| -------------------------------------------- | -------------------------------------------------------- |
| "Invalid"                                    | "Please enter a valid email address."                   |
| "Error"                                      | "Password must be at least 8 characters."               |
| "Required"                                   | "Name is required."                                     |
| "Nope"                                       | "Start date must be before end date."                   |
| Nothing (just red border)                    | Always pair with a specific text message.               |

Every error message MUST:
1. Identify what field is in error (implied by position is acceptable)
2. State what went wrong
3. Provide a clear instruction for how to fix it

### 3.3 Multiple Errors

When a form has multiple validation errors:
- Each field shows its own inline error
- A banner alert at the top of the form summarizes all errors:
  ```
  "Please fix 3 errors before submitting: invalid email, missing name, password too short."
  ```
- Auto-scroll to the first error field on submit attempt
- Focus the first error field after scroll

## 4. Select Dropdown

### 4.1 Trigger Styling

The select trigger button matches the input field exactly in:
- Height (40-48px default)
- Border (neutral-200 default, same hover/focus/error states)
- Border radius (rounded-md, 8px)
- Padding (same as input)
- Font (14px)

Unique to the select trigger:
- Chevron-down icon (16px) on the right, rotates 180° on open
- Selected value text: text-primary
- Placeholder text when nothing selected: text-muted, format: `"Select a {thing}..."`

### 4.2 Expanded Panel

```
┌─────────────────────────────┐
│  City                       │
│  ┌─────────────────────────┐│
│  │ San Francisco       ▾   ││  ← trigger
│  └─────────────────────────┘│
│  ┌─────────────────────────┐│
│  │ 🔍 Search cities...     ││  ← optional search input
│  │─────────────────────────││
│  │ ✓ San Francisco         ││  ← selected option (accent-500 check)
│  │   Los Angeles           ││  ← normal option
│  │   New York              ││  ← hovered (accent-50 bg)
│  │   Chicago               ││
│  │   Houston               ││
│  │   ...                   ││  ← scroll for more
│  └─────────────────────────┘│
└─────────────────────────────┘
```

Specs:
- Border: 1px solid neutral-200
- Shadow: shadow-lg (0 4px 12px rgba(0,0,0,0.1))
- Border radius: rounded-md (8px)
- Max height: 300px, then scroll (overflow-y: auto)
- Min width: matches trigger width
- Z-index: 50 (above form content, below modal)

### 4.3 Option States

| State      | Background      | Text         | Icon             |
| ---------- | --------------- | ------------ | ---------------- |
| Default    | transparent     | text-primary | none             |
| Hover      | accent-50       | text-primary | none             |
| Selected   | transparent     | accent-700   | accent-500 ✓     |
| Disabled   | transparent     | neutral-300  | none             |
| Active     | accent-100      | accent-800   | accent-500 ✓     |

Option padding: 8px vertical, 12px horizontal. Checkmark icon: 16px, positioned right.

### 4.4 Keyboard Navigation

| Key        | Action                                     |
| ---------- | ------------------------------------------ |
| Space/Enter| Open dropdown (closed), select option (open) |
| Arrow Down | Move focus to next option                  |
| Arrow Up   | Move focus to previous option              |
| Home       | Jump to first option                       |
| End        | Jump to last option                        |
| Escape     | Close dropdown                             |
| Tab        | Close dropdown, move to next field         |
| Type letter| Jump to first option starting with letter  |

### 4.5 Search Within Select

When options exceed 12 items, the dropdown panel MUST include a search input at the top:
- Sticky within the panel (does not scroll with options)
- Auto-focuses when panel opens
- Filters options in real-time (150ms debounce)
- Shows "No results" message when search matches nothing

## 5. Checkbox

### 5.1 Visual Specification

```
┌──────────────────────────────────────┐
│                                      │
│  Unchecked:                          │
│  ┌──┐ Agree to terms                │  ← entire row is clickable
│  └──┘                                │
│                                      │
│  Checked:                            │
│  ┌──┐ Agree to terms                │
│  │✓ │                                │
│  └──┘                                │
│                                      │
│  Indeterminate:                      │
│  ┌──┐ Select all items              │
│  │━ │                                │
│  └──┘                                │
│                                      │
└──────────────────────────────────────┘
```

Specs:
- Box size: 16-20px square (use 18px default, 16px compact)
- Border radius: rounded (4px) — not fully round, not square
- Border (unchecked): 1px solid neutral-200
- Fill (unchecked): white
- Border (checked): 1px solid accent-500
- Fill (checked): accent-500
- Checkmark: white, 12px, centered, path-based SVG (stroke-width: 2)
- Indeterminate dash: white, 10px wide, 2px tall, centered

### 5.2 Label Interaction

- The ENTIRE row from checkbox left edge to text right edge is clickable
- Clicking the label toggles the checkbox
- Cursor: pointer over the entire row
- Gap between checkbox box and label text: 8-12px (use 10px default)

Label specs:
- Font size: 14px (same as input labels)
- Font weight: 400 (normal, not medium — labels on checkboxes are body text)
- Color: text-primary
- Vertical alignment: center with checkbox box

### 5.3 Checkbox Group

When grouping multiple checkboxes:
- Spacing between checkboxes: 8-12px vertical (use 10px)
- Group label (optional): above the group, 14px font-medium, same as input label style
- Group helper text: below the group, 12px text-muted, same as input helper style

```
┌─────────────────────────────┐
│  Notification Preferences   │  ← group label
│                             │
│  ☑ Push notifications      │
│  ☑ Email notifications     │
│  ☐ SMS notifications       │
│                             │
│  Select how you want to be  │  ← group helper
│  notified.                  │
└─────────────────────────────┘
```

### 5.4 Error State

When a checkbox (or group) fails validation:
- Each unchecked checkbox in the required group gets danger-500 border
- Error message appears below the group: `"Please select at least one option."`

## 6. Radio Group

### 6.1 Visual Specification

Same color and size system as checkbox, but the shape is a **circle**:

```
┌──────────────────────────────────────┐
│                                      │
│  Unchecked:                          │
│  ○ Option A                          │
│                                      │
│  Checked:                            │
│  ● Option A                          │  ← outer ring: accent-500
│                                      │     inner dot: accent-500 (6px)
│  Hover (unchecked):                  │
│  ◉ Option A                          │  ← outer ring: neutral-300
│                                      │
└──────────────────────────────────────┘
```

Specs:
- Circle size: 16-20px (use 18px default)
- Outer ring (unchecked): 1px solid neutral-200
- Outer ring (checked): 1px solid accent-500
- Inner dot (checked): 6px solid accent-500, centered
- Outer ring (hover unchecked): 1px solid neutral-300
- Outer ring (error): 1px solid danger-500

### 6.2 Layout Rules

| Option Count | Layout   | Spacing              | Rationale                                 |
| ------------ | -------- | -------------------- | ----------------------------------------- |
| 2-3 options  | Inline   | 16-24px between      | Small set fits horizontally, saves space  |
| 4+ options   | Stacked  | 8-12px vertical      | Vertical scanning is faster, more legible |

Inline radio group example:
```
○ Option A    ○ Option B    ○ Option C
```

Stacked radio group example:
```
○ Option A
○ Option B
○ Option C
○ Option D
```

### 6.3 Label Rules

- Radio labels use 14px, weight 400 (body text, same as checkbox labels)
- Entire row is clickable (radio circle + label text)
- Gap between circle and label: 8-12px
- Group label (above): 14px font-medium
- Group helper/error (below): 12px text-muted or 14px danger-500

### 6.4 Mandatory Selection

Radio groups are exclusively for mandatory selections. For optional single-select with deselect ability, use a select dropdown with a "None" option instead.

## 7. Toggle / Switch

### 7.1 Visual Specification

```
OFF STATE (default):
┌─────────────────────────────────┐
│  Notifications: [⚪────] OFF   │  ← label left of toggle
└─────────────────────────────────┘
                     │    │
                     │    └── track: 44x24px, neutral-200, rounded-full
                     └─────── knob: 20x20px, white, shadow-sm, left-aligned

ON STATE (checked):
┌─────────────────────────────────┐
│  Notifications: [────⚪] ON    │  ← label left of toggle
└─────────────────────────────────┘
                     │    │
                     │    └── track: 44x24px, accent-500, rounded-full
                     └─────── knob: 20x20px, white, shadow-sm, right-aligned
```

Specs:
- Track dimensions: 44px wide × 24px tall
- Track border radius: rounded-full (12px)
- Track background: neutral-200 (off), accent-500 (on)
- Knob dimensions: 20px × 20px (2px inset from track edges)
- Knob background: white
- Knob shadow: shadow-sm (0 1px 3px rgba(0,0,0,0.15))
- Transition: transform 200ms ease, background-color 200ms ease

### 7.2 Label Position

Label must be placed **to the left** or **to the right** of the toggle, never ambiguous.

```
CORRECT:
Notifications  [────⚪]     ← label left (preferred for form alignment)
[────⚪]  Notifications     ← label right (acceptable)

WRONG:
        [────⚪]            ← no label at all
    Notifications          ← label above (but what does it describe?)
        [────⚪]
```

Left-aligned label is preferred because it aligns with other form labels that are above their inputs.

### 7.3 Touch Target

The entire toggle row (label + switch) should be tap-responsive. Minimum tap area: 44px tall (the entire row). The track itself is already 24px; allocate the remaining 20px to the label area with centered alignment.

### 7.4 Disabled State

- Opacity: 0.5
- Cursor: not-allowed
- No animation on click attempt
- Track color remains (off or on) but at 50% opacity through the container

## 8. Textarea

### 8.1 Visual Treatment

Textarea follows ALL the same rules as a standard input field for:
- Border states (default, hover, focus, error, disabled, read-only)
- Border radius (rounded-md, 8px)
- Padding (12px horizontal, 8-12px vertical)
- Font (14px)
- Label placement (above)
- Helper/error/character count (below)

### 8.2 Resize Rules

- `resize: vertical` ONLY
- Never allow horizontal resize (breaks layout)
- Minimum height: 80px (approximately 3 lines of text)
- No maximum height by default; content scrolls when it exceeds the defined height

### 8.3 Auto-Resize Behavior

When auto-resize is enabled (rare, use sparingly):
- Textarea grows vertically as content is typed
- Maximum height after which scroll takes over: 300px
- Smooth height transition: height 100ms ease
- Never shrink below the minimum height of 80px

### 8.4 Character Count with Textarea

```
┌─────────────────────────────┐
│  Description                │
│  ┌─────────────────────────┐│
│  │ This product is design  ││
│  │ ed for professional     ││
│  │ use in office           ││
│  │ environments. It is ... ││
│  │                         ││
│  └─────────────────────────┘│
│  Brief description         │  ← helper
│                       128/500│  ← count (right-aligned)
└─────────────────────────────┘
```

When character count and helper text both exist, they share the same line: helper left, count right. If overflow is a concern, stack them (helper above count, 2px gap).

## 9. Form Layout Patterns

### 9.1 Single Column (Preferred)

Single-column forms are the default and strongly preferred layout:

```
┌────────────────────────────────────┐
│  Contact Form                      │
│                                    │
│  Full Name *                       │
│  ┌──────────────────────────────┐  │
│  │                              │  │
│  └──────────────────────────────┘  │
│                                    │  ← 24px gap
│  Email Address *                   │
│  ┌──────────────────────────────┐  │
│  │                              │  │
│  └──────────────────────────────┘  │
│                                    │  ← 24px gap
│  Message *                         │
│  ┌──────────────────────────────┐  │
│  │                              │  │
│  │                              │  │
│  └──────────────────────────────┘  │
│                                    │  ← 48px gap
│  ┌──────────────────────────────┐  │
│  │         Send Message         │  │
│  └──────────────────────────────┘  │
└────────────────────────────────────┘
```

Max width: 560px for standalone forms (not full page width). Center the form container.

### 9.2 Two Column (Limited Use)

Use two-column layout ONLY for paired fields:

```
┌────────────────────────────────────────────────┐
│  ┌─────────────────────┐ ┌───────────────────┐ │
│  │ First Name *        │ │ Last Name *       │ │
│  └─────────────────────┘ └───────────────────┘ │
│  ┌─────────────────────┐ ┌───────────────────┐ │
│  │ City                │ │ State             │ │
│  └─────────────────────┘ └───────────────────┘ │
│  ┌─────────────────────┐ ┌───────────────────┐ │
│  │ Start Date          │ │ End Date          │ │
│  └─────────────────────┘ └───────────────────┘ │
└────────────────────────────────────────────────┘
```

Rules for two-column:
- Only pair fields that are logically related (first/last name, city/state, start/end date)
- Equal width columns (use `grid-template-columns: 1fr 1fr`, gap: 16-24px)
- Never split unrelated fields across columns (e.g., don't put email left, password right)
- On mobile (<768px), collapse to single column
- Gap between column pairs: 24px vertical

### 9.3 Grouped Sections

For longer forms (>6 fields), group fields into logical sections:

```
┌────────────────────────────────────┐
│  Personal Information              │  ← section heading (16px, font-semibold)
│  ──────────────────────────────    │  ← divider (neutral-100, 1px)
│                                    │
│  Full Name *                       │
│  ┌──────────────────────────────┐  │
│  │                              │  │
│  └──────────────────────────────┘  │
│                                    │
│  Email *                           │
│  ┌──────────────────────────────┐  │
│  │                              │  │
│  └──────────────────────────────┘  │
│                                    │  ← 32-48px gap between sections
│  Address Details                  │
│  ──────────────────────────────    │
│                                    │
│  Street Address                    │
│  ┌──────────────────────────────┐  │
│  │                              │  │
│  └──────────────────────────────┘  │
│                                    │
│  City          State   Zip         │
│  ┌──────────┐ ┌─────┐ ┌────────┐  │
│  │          │ │     │ │        │  │
│  └──────────┘ └─────┘ └────────┘  │
└────────────────────────────────────┘
```

Section heading specs:
- Font: 16px, weight 600 (semibold)
- Color: text-primary
- Divider: 1px solid neutral-100, full width below heading
- Divider margin: 8px above, 16px below (or 24px total from heading to first field)

### 9.4 Column Pair Within Sections

Two-column layout may be used within a section for truly paired fields. A section containing `[First Name] [Last Name]` followed by a full-width `[Email]` is acceptable. A section that is entirely two-column rows is also acceptable.

## 11. Submit Button

### 11.1 Width Rules

- **Mobile (<640px):** Full width, 48px height
- **Desktop (>640px):** Natural width (content + padding), 40-48px height
- **Form footer:** Aligned left or right depending on context. Right-align for standard forms, left-align in dialogs (paired with cancel button).

### 11.2 Button Design

Primary submit button:
- Background: accent-500
- Text color: white
- Border radius: rounded-md (8px)
- Padding: 12px 24px horizontal, matches input height
- Font weight: font-medium (500)
- Hover: accent-600 (10% darker)
- Active: accent-700 (20% darker)
- Focus ring: same as input focus ring (2px accent-500/25, offset 2px)

### 11.3 Loading State

```
┌───────────────────────────────┐
│  [◌]  Saving...               │  ← spinner (16px) + text, pointer-events: none
└───────────────────────────────┘
```

- Spinner: 16px, white, animated (rotate, 600ms linear infinite)
- Text changes from action verb ("Save Changes") to gerund ("Saving...")
- Button opacity: 0.8 (slightly dimmed but not disabled-looking)
- Pointer events: none (prevents double-submit)
- All other form inputs become disabled during submit
- On error: revert button to active state, show error message
- On success: redirect, show toast, or show inline success

### 11.4 Disabled State

- Opacity: 0.5
- Cursor: not-allowed
- Background: neutral-300, text: neutral-500 (no accent color)
- Tooltip must explain WHY disabled:
  ```
  Hover: "Complete all required fields to continue"
  ```
- Never show a disabled submit button without a tooltip explaining the condition

### 11.5 Secondary Actions

When a form needs a secondary action (e.g., "Cancel", "Save as Draft"):
- Position to the left of the primary button with 12-16px gap
- Style: ghost or outline (transparent bg, neutral-300 border, neutral-700 text)
- Same height as primary button

## 12. Anti-Slop Rules for Forms

The following patterns are **forbidden** and must never appear in generated designs:

1. **Inline labels** — Labels must be above inputs. Never `Label: [..............]`
2. **Missing error text** — A red border alone is not an error message. Every error state includes descriptive text below the field.
3. **Placeholder-only labeling** — If there is no `<label>` element (visible or hidden), the design is broken. Placeholders are hints, not labels.
4. **Autocapitalize off on name fields** — Devices autocapitalize first letters. Do not suppress this on name, given-name, family-name, or organization fields. Use `autocapitalize="off"` only on email, URL, and password fields.
5. **Select with native HTML on forms over 4 fields** — Custom-select with search for medium+ form density. Native `<select>` only for simple pickers with <6 options.
6. **Submit button that is smaller than inputs** — The submit button must be at least as tall as the input fields (40-48px).
7. **Form fields without labels** — Every input, select, textarea, radio group, and checkbox group has a visible label.
8. **Colored submit buttons that are not accent color** — Submit uses the brand accent, not green for "success" or random colors. The only exception is destructive confirmations (danger-500).
9. **Required asterisk on all fields** — When all fields are required, add a single note at the top ("All fields are required") instead of asterisks everywhere. Only mark truly optional fields as "(optional)".
10. **Date inputs without labels or tooltips explaining expected format** — `MM/DD/YYYY` or locale-appropriate format must be communicated.

| Situation                                     | Recommendation                                      |
| --------------------------------------------- | --------------------------------------------------- |
| 1-4 fields, simple data                       | Single column, 40px inputs, full-width mobile       |
| 5-10 fields, mixed complexity                 | Single column with 2-3 sections, 40px inputs        |
| 11+ fields                                    | Sections with progress indicator, 40px inputs       |
| First name + Last name                        | Two-column (equal width), collapse on mobile        |
| City, State, Zip                              | Three-column (2:1:1 ratio), collapse on mobile      |
| Date range                                    | Two-column with "to" text between, collapse mobile  |
| Settings / preferences                        | Sections with toggles and selects, no submit button |
| Login / sign-up                               | Single column, compact, full-width button           |
| Checkout / payment                            | Sections, payment area visually distinct (Panel)    |
| Inline search / filter                        | 32px compact input, icon-prefix, no label           |
| Data table filter                             | 28-32px dense inputs, horizontal row layout         |
