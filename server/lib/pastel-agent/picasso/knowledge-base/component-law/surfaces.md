# Surface Component Law

> Defines the canonical design rules for all surface and container components generated by Picasso. Every card, band, panel, inset, full-bleed, and glass surface must follow these rules exactly. Deviations constitute design defects.

---

## 1. Surface Type Decision Tree

```
                         ┌─────────────────────────┐
                         │  What is the content?    │
                         └───────────┬─────────────┘
                                     │
              ┌──────────────────────┼──────────────────────┐
              ▼                      ▼                      ▼
     Is this a discrete      Is this a section      Is this a focused
     content block?          divider/grouping?      task container?
              │                      │                      │
              ▼                      ▼                      ▼
          ┌────────┐          ┌────────────┐         ┌────────────┐
          │  CARD  │          │ Is it a     │         │   PANEL    │
          │        │          │ hero/focal  │         │            │
          │ border │          │ area?       │         │ bg-card    │
          │ shadow │          │      │      │         │ border     │
          │ radius │          │  Yes │ No   │         │ radius-xl  │
          └────────┘          │      │      │         └────────────┘
                              ▼      ▼
                        ┌─────────┐ ┌─────────┐
                        │FULL-BLEED│ │  BAND   │
```

## 2. Card

### 2.1 Visual Specification

```
┌─────────────────────────────┐
│                             │
│  Card Title                 │  ← 16-18px, font-semibold
│                             │
│  Brief description of what  │  ← 14px, text-muted
│  this card contains.        │
│                             │
│  ───────────────────────    │  ← optional divider (neutral-100)
│                             │
│  [Action Button]            │  ← optional footer action
│                             │
└─────────────────────────────┘
  ↑ border: 1px neutral-200, shadow-sm, rounded-lg (10-16px)
```

### 2.2 Full Specifications

| Property        | Value                                    |
| --------------- | ---------------------------------------- |
| Background      | white (or bg-card if using base layer)   |
| Border          | 1px solid neutral-200                    |
| Border radius   | rounded-lg (10-16px)                     |
| Shadow          | shadow-sm: 0 1px 3px rgba(0,0,0,0.06)   |
| Padding         | 20-24px (use 24px default)               |
| Hover           | shadow-md + translateY(-2px), 150ms ease |

### 2.3 When to Use Cards

```
CORRECT uses:
✓ Stat/metric displays (revenue, active users, conversion rate)
✓ Feature highlights (icon + title + description)
✓ Content previews (article snippet, product summary)
✓ Profile summaries (avatar + name + role + stats)
✓ Quick actions (a set of related buttons/links)

WRONG uses:
✗ Full-page form (use Panel)
✗ Section heading only (use Band or Plain)
✗ Embedded code (use Inset)
✗ Navigation sidebar (it IS the surface)
✗ Entire page layout (use background + content)
```

### 2.4 Card Density Levels

| Context            | Padding | Title Size | Body Size |
| ------------------ | ------- | ---------- | --------- |
| Dense (dashboards) | 16px    | 14px       | 12px      |
| Default            | 24px    | 16px       | 14px      |
| Relaxed (landing)  | 32px    | 18-20px    | 16px      |

### 2.5 Maximum Cards Per Screen

Never show more than **3 cards per row** on a dashboard overview. Exceeding 3 cards creates visual clutter and reduces each card's impact. If you need a 4-column grid, use a Band section with icon+text items, not cards.

### 2.6 Card Groups

When multiple cards appear together:
- Equal height (via `align-items: stretch` or `min-height`)
- Consistent internal structure (same title/body/footer pattern)
- Grid gap: 16-24px (use 20px default)
- All clickable or none clickable (don't mix in one row)

## 3. Band

### 3.1 Visual Specification

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  Section Heading                                             │
│  ─────────────                                               │
│                                                              │
│  Supporting text that explains what this section contains.   │
│                                                              │
│  ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐        │
│  │ Feature  │ │ Feature  │ │ Feature  │ │ Feature  │        │
│  └──────────┘ └──────────┘ └──────────┘ └──────────┘        │
│                                                              │
└──────────────────────────────────────────────────────────────┘
  ↑ bg-muted/50, full-width, no border, no shadow
```

### 3.2 Full Specifications

| Property          | Value                                    |
| ----------------- | ---------------------------------------- |
| Background        | bg-muted at 50% opacity (neutral-50 on light, neutral-900 on dark) |
| Width             | 100% (full viewport/content width)       |
| Border            | none                                     |
| Shadow            | none                                     |
| Radius            | none (full-width, square edges)          |
| Padding Y         | 48-96px (use 64px default)               |
| Padding X         | matches page content padding             |

### 3.3 When to Use Bands

```
CORRECT uses:
✓ Section grouping (Features, Pricing, Testimonials, FAQ)
✓ Alternating content (text left + image right per section)
✓ Testimonials section (band with quote cards inside)
✓ Call-to-action sections (emphasis via contrast)
✓ "How it works" sections with numbered steps

WRONG uses:
✗ Single content block (use Card)
✗ Focused task area (use Panel)
✗ Content that needs border/shadow separation (use Card)
✗ Code snippets (use Inset)
```

### 3.4 Band Contrast

| Page Background   | Band Background        |
| ----------------- | ---------------------- |
| white             | neutral-50 (#fafafa)   |
| neutral-50        | white                  |
| neutral-100       | neutral-50 or white    |
| neutral-900 (dark)| neutral-800            |

The contrast must be subtle enough not to distract but clear enough to delineate sections.

## 4. Panel

### 4.1 Visual Specification

```
┌─────────────────────────────────────────┐
│                                         │
│  Settings                               │
│  ────────────────────────────────       │
│                                         │
│  Profile Name                           │
│  ┌─────────────────────────────────┐    │
│  │                                 │    │
│  └─────────────────────────────────┘    │
│                                         │
│  Email                                  │
│  ┌─────────────────────────────────┐    │
│  │                                 │    │
│  └─────────────────────────────────┘    │
│                                         │
│                       [Save Changes]    │
│                                         │
└─────────────────────────────────────────┘
  ↑ bg-card, border: 1px neutral-200, rounded-xl (12-16px)
```

### 4.2 Full Specifications

| Property      | Value                                    |
| ------------- | ---------------------------------------- |
| Background    | bg-card (subtly different from page bg)  |
| Border        | 1px solid neutral-200                    |
| Border radius | rounded-xl (12-16px)                     |
| Shadow        | none (or shadow-sm if on white page)     |
| Padding       | 24-32px                                  |

### 4.3 When to Use Panels

```
CORRECT uses:
✓ Forms (new project, edit profile, checkout)
✓ Settings pages (grouped configuration options)
✓ Focused task areas (compose message, write document)
✓ Detail view containers (project details, user profile view)
✓ Auth screens (login, signup — form in a panel, centered)

WRONG uses:
✗ Repeating content blocks (use Card)
✗ Page sections (use Band)
✗ Dashboards with mixed widgets (use Cards)
✗ Code/embedded content (use Inset)
✗ Navigation (use Glass or background)
```

### 4.4 Panel vs Card — The Distinction

| Aspect       | Card                            | Panel                          |
| ------------ | ------------------------------- | ------------------------------ |
| Purpose      | Display/preview content         | Task completion, focused work  |
| Interaction  | Read-oriented, may be clickable | Write-oriented, form fields    |
| Multiplicity | Multiple per page (grid)        | Usually ONE per page           |
| Shadow       | Always has shadow               | Rarely has shadow              |
| Content      | Passive: text, stats, previews  | Active: forms, inputs, actions |

## 5. Inset

### 5.1 Visual Specification

```
┌──────────────────────────────────────────┐
│  Regular page content here. To install:  │
│                                          │
│  ┌────────────────────────────────────┐  │
│  │  $ npm install @acme/sdk           │  │  ← inset block
│  │  $ acme init --project my-app      │  │     background: neutral-50
│  └────────────────────────────────────┘  │
│                                          │
│  This will set up the project...         │
└──────────────────────────────────────────┘
```

### 5.2 Full Specifications

| Property      | Value                                    |
| ------------- | ---------------------------------------- |
| Background    | neutral-50 (on white) or neutral-900 (on dark) |
| Border        | none (recessed feel — no border, no shadow) |
| Border radius | rounded-md (6-8px, subtle)               |
| Padding       | 16-20px                                  |

### 5.3 When to Use Inset

```
CORRECT uses:
✓ Code blocks and syntax-highlighted snippets
✓ Embedded content (tweets, videos, iframes)
✓ File previews (PDF, image thumbnails in context)
✓ Console/terminal output
✓ Callouts with a different background tone

WRONG uses:
✗ Cards (cards pop forward, insets recess backward)
✗ Forms (use Panel)
✗ Navigation (use Glass)
✗ Elements that need to stand out (insets de-emphasize)
```

Insets convey: "This content came from somewhere else." It signals that the content within is external, referenced, or system-generated.

## 6. Full-Bleed

### 6.1 Visual Specification

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                    HERO HEADLINE                             │
│           Subheadline describing the value prop               │
│                                                              │
│                    [Primary CTA] [Secondary]                  │
│                                                              │
└──────────────────────────────────────────────────────────────┘
  ↑ edge-to-edge background, no horizontal padding, inner container centers content
```

### 6.2 Full Specifications

| Property        | Value                                    |
| --------------- | ---------------------------------------- |
| Width           | 100vw (full viewport width)              |
| Background      | accent-500, gradient, or image           |
| Border          | none                                     |
| Shadow          | none                                     |
| Radius          | none (square edges, edge-to-edge)        |
| Padding Y       | 80-160px                                 |
| Inner container | max-width: 800-1200px, mx: auto          |

### 6.3 When to Use Full-Bleed

```
CORRECT uses:
✓ Hero sections (landing page above the fold)
✓ Accent bands (single accent-500 full-bleed between plain sections)
✓ Deliberate visual breaks (separating major page sections)
✓ CTAs that need maximum visual impact
✓ Full-width image backgrounds with overlaid text

WRONG uses:
✗ Standard content sections (use Band)
✗ Repeated page patterns (full-bleed loses impact if overused)
✗ Forms or task areas (use Panel)
✗ Two adjacent full-bleed sections (need plain/band between them)
```

### 6.4 Inner Container

Full-bleed blocks MUST use an inner container to constrain content width. Max-width: 1200px general, 800px text-heavy hero sections.

## 7. Glass

### 7.1 Visual Specification

Glass is a **specialized translucent surface** reserved exclusively for floating UI elements:

```
┌──────────────────────────────────────────┐
│  Tooltip text appears here               │  ← glass surface
└──────────────────────────────────────────┘
  ↑ background: rgba(255,255,255,0.7), backdrop-blur: 8px, border: 1px rgba(0,0,0,0.05)
```

### 7.2 Full Specifications

| Property      | Value                                    |
| ------------- | ---------------------------------------- |
| Background    | rgba(255,255,255,0.7) on light theme     |
| Backdrop blur | 8-12px                                   |
| Border        | 1px solid rgba(0,0,0,0.05)               |
| Border radius | rounded-lg (8-12px)                      |
| Shadow        | shadow-lg                                |

### 7.3 When to Use Glass

```
CORRECT uses:
✓ Navigation bars (topbar with blur for scroll transparency)
✓ Tooltips and popovers
✓ Context menus / dropdowns
✓ Floating action panels

WRONG uses:
✗ Content cards (use Card — glass is for floating UI, not content)
✗ Forms (use Panel — glass lacks the defined boundary forms need)
✗ Text-heavy content blocks (blur makes text harder to read)
✗ Dashboards (glass over content creates visual noise)
```

## 8. Surface Rhythm

### 8.1 The Alternation Rule

Adjacent sections must NOT use the same surface type. This is a hard rule:

```
CORRECT page rhythm:
Full-Bleed (hero)
  → Plain (intro text)
    → Card (feature grid)
      → Band (testimonials)
        → Plain (pricing)
          → Full-Bleed (CTA)
            → Plain (footer)

WRONG page rhythm:
Band → Band → Band (monotonous — no contrast)
Card → Card → Card → Card → Card (reads as a template)
Full-Bleed → Full-Bleed (aggressive, fatiguing)
```

### 8.2 Permitted Transitions

| From        | To                   |
| ----------- | -------------------- |
| Full-Bleed  | Plain or Card        |
| Band        | Plain, Card, Full-Bleed |
| Plain       | Band, Card, Full-Bleed, Panel |
| Card        | Plain, Band          |
| Panel       | Plain, Card          |
| Inset       | Plain (always goes back to Plain) |

## 9. Nesting Rules

### 9.1 What Can Go Inside What

| Parent  | Card Inside | Card Inside* | Band Inside | Panel Inside | Inset Inside |
| ------- | ----------- | ------------ | ----------- | ------------ | ------------ |
| Card    | AVOID       | AVOID        | NEVER       | NEVER        | NEVER        |
| Band    | OK          | OK           | AVOID       | OK           | OK           |
| Panel   | OK          | AVOID        | NEVER       | AVOID        | OK           |
| Plain   | OK          | OK           | OK          | OK           | OK           |
| Inset   | NEVER       | NEVER        | NEVER       | NEVER        | NEVER        |

*Card Inside = nesting one card within another card

### 9.2 Key Nesting Rules

1. **Card inside Band: OK.** A testimonial band containing testimonial cards is correct.
2. **Card inside Card: AVOID.** Nesting cards creates ambiguous boundaries. Use a divider instead.
3. **Band inside Card: NEVER.** A band's purpose (full-width section grouping) contradicts a card's purpose (discrete block).
4. **Panel inside Band: OK.** A form panel inside a settings band section is correct.
5. **Inset inside anything except Inset: OK.** Insets are simple recessed blocks that can nest anywhere.

```
Full-Bleed (hero — accent bg, headline, CTA)
  → Plain (features grid)
    → Band (testimonials — neutral-50 bg)

        → Plain (footer)
```

```
Panel (main content: detail view, form, or focused area)
  → Card (related items — grid of related content)
    → Plain (comments / activity section)
```

## 12. Anti-Slop Rules for Surfaces

1. **Never all-cards layout** — A page consisting entirely of cards reads as a template. Vary surface types to create rhythm and hierarchy.
2. **Never two adjacent same-surface sections** — Band-Band, Card-Card, FullBleed-FullBleed. The alternation rule exists for visual breathing room.
3. **Never surface mixing** — Do not apply a band background (bg-muted) AND a card border/shadow to the same container. Each surface type has one visual treatment.
4. **Never shadow on every element** — Shadows create elevation. If everything is elevated, nothing is. Reserve shadows for cards, modals, and floating UI.
5. **Never glass for content** — Glass (backdrop-blur) is for floating UI only, never for content blocks. Blur behind text degrades readability.
6. **Never band background without sufficient contrast** — A band that is barely distinguishable from the page background fails at its job (visual separation).
7. **Never full-bleed without inner container** — Full-width text is unreadable. Always constrain content with an inner container.
8. **Never nesting card in card** — If you feel the need to nest cards, use a list with dividers inside one card instead.
9. **Never inset for interactive elements** — Insets are recessed and passive. They should never contain forms, buttons, or interactive controls.
10. **Never card for full-page forms** — Use Panel. Cards are for display, panels are for task completion.

## 13. Summary — Surface Decision Matrix

| Content Type                          | Surface     | Notes                                     |
| ------------------------------------- | ----------- | ----------------------------------------- |
| Single stat or metric                 | Card        | Compact, with label + value + trend       |
| Group of stats (2-4)                  | Cards (grid)| 2-4 cards in a row, equal height          |
| Feature showcase (3-6 items)          | Cards (grid)| Icon + title + description                |
| Full page section                     | Band        | Neutral background, full-width            |
| Alternating content sections          | Band + Plain| Band → Plain → Band rhythm                |
| Hero / above-the-fold                 | Full-Bleed  | Edge-to-edge, accent or image bg          |
| Call to action section                | Full-Bleed  | High impact before footer                 |
| Form (create, edit, checkout)         | Panel       | Focused task container, border + radius   |
| Settings / configuration              | Panel       | Grouped fields, sections                  |
| Auth screen (login, signup)           | Panel       | Centered, max-width 400-480px             |
| Code block / snippet                  | Inset       | Recessed background, monospace font       |
| Embedded content (video, tweet)       | Inset       | Recessed feel, external content signal    |
| Terminal / console output             | Inset       | Dark variant, monospace                   |
| Navigation bar (topbar, sidebar)      | Glass or bg  | Glass if scroll-transparent, else solid   |
| Tooltip / popover                     | Glass       | Translucent + blur, elevated              |
| Dropdown menu                         | Glass       | Translucent + blur, shadow-lg             |
| Plain text section                    | Plain       | No surface treatment, just content        |
| Comments / activity feed              | Plain       | List-based, dividers between items        |
