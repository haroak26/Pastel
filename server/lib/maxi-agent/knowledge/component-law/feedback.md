# Feedback Component Law

> Defines the canonical design rules for all user feedback components generated by Picasso. Every toast, dialog, banner, loading state, empty state, error state, and confirmation pattern must follow these rules exactly. Deviations constitute design defects.

---

## 1. Toast / Notification

### 1.1 Visual Specification

```
                                                      ┌─────────────────────────┐
                                                      │ ✓  Changes saved        │
                                                      │    Your profile has been │
                                                      │    updated successfully. │
                                                      │                    Undo  │
                                                      └─────────────────────────┘
                                                              ↑
                                                fixed top-right, z-index 100
```

### 1.2 Positioning

- **Default position:** top-right (32px from top, 32px from right)
- **Alternative position:** bottom-right (for apps with fixed topbar)
- **Alignment:** toast stack grows downward from the initial position
- **Max width:** 360-400px (with a minimum of 280px)
- **Z-index:** 100 (above modals, dialogs, and overlays if needed)

### 1.3 Toast Types

| Type      | Icon               | Icon Color   | Left Border      | Background |
| --------- | ------------------ | ------------ | ---------------- | ---------- |
| Success   | checkmark-circle   | green-500    | none (or green-500 3px) | white |
| Error     | x-circle / alert   | red-500      | none (or red-500 3px)   | white |
| Warning   | alert-triangle     | amber-500    | none (or amber-500 3px) | white |
| Info      | info-circle        | blue-500     | none (or blue-500 3px)  | white |

Recommended toast design:
- White background
- Shadow: shadow-lg (0 4px 16px rgba(0,0,0,0.12))
- Border: 1px solid neutral-200
- Border radius: rounded-lg (8-10px)
- Padding: 16px
- Icon: 20px, left-aligned
- Content area: 12px gap from icon

### 1.4 Toast Anatomy

```
┌──────────────────────────────────────┐
│ [icon]  Title (14px, font-medium)    │  ← title
│         Description (13px, muted)    │  ← optional body text
│         [Action]                 ✕   │  ← optional action + close button
└──────────────────────────────────────┘
```

| Element       | Specs                                          |
| ------------- | ---------------------------------------------- |
| Icon          | 20px, semantic color, left-aligned, top-aligned|
| Title         | 14px, font-medium, text-primary                |
| Description   | 13px, text-muted (neutral-500), optional       |
| Action        | 13px, font-medium, accent-500, optional button |
| Close button  | 16px, neutral-400, top-right, hover:neutral-600|
| Max lines     | 2 for description (truncate beyond)            |

### 1.5 Animation

Entry animation:
```
@keyframes toast-slide-in {
  from {
    transform: translateX(100%);
    opacity: 0;
  }
  to {
    transform: translateX(0);
    opacity: 1;
  }
}
Duration: 200ms, easing: ease-out
```

Exit animation:
```
@keyframes toast-slide-out {
  from {
    transform: translateX(0);
    opacity: 1;
  }
  to {
    transform: translateX(100%);
    opacity: 0;
  }
}
Duration: 150ms, easing: ease-in
```

### 1.6 Auto-Dismiss

| Property          | Value                                   |
| ----------------- | --------------------------------------- |
| Default duration  | 5000ms (5 seconds)                      |
| Error duration    | 7000ms (longer, user may need to read)  |
| Manual dismiss    | Click close (✕) button                  |
| Pause on hover    | timer pauses while cursor is over toast |
| Max visible       | 3 toasts at once (stack vertically)     |

When a 4th toast arrives while 3 are visible:
- Dismiss the oldest (lowest in stack)
- OR queue it and show after the oldest auto-dismisses

### 1.7 Undo Pattern

For destructive or consequential actions (delete, archive, send):
```
┌──────────────────────────────────────────┐
│ 🗑  Item deleted                          │
│    "Project Alpha" has been deleted.      │
│                              Undo  ✕     │
└──────────────────────────────────────────┘
```

Clicking "Undo" reverses the action and dismisses the toast. The undo button must be visibly prominent (font-medium, accent-500 or primary color).

Never show an undo toast for:
- Actions that cannot be undone (permanent data wipe without soft-delete)
- Read operations (view, open, navigate)
- Actions the user explicitly confirmed (unless the confirmation provided an "undo" option)

## 2. Banner / Alert

### 2.1 Visual Specification

```
┌──────────────────────────────────────────────────────────────┐
│  ℹ️  Your subscription will expire in 7 days.  [Renew Now]  ✕│
└──────────────────────────────────────────────────────────────┘
     ↑ full-width, below topbar, above content
```

### 2.2 Positioning

- **Position:** below topbar (if present), above all page content
- **Width:** full-width of the content area (not full viewport — respects sidebar)
- **Sticky:** optional (top: topbar-height) for persistent alerts
- **Z-index:** 30 (below sidebar/topbar, above content)

### 2.3 Banner Types

| Type      | Background    | Border Left (3px) | Icon Color | Text Color |
| --------- | ------------- | ----------------- | ---------- | ---------- |
| Info      | blue-50       | blue-500          | blue-500   | blue-800   |
| Success   | green-50      | green-500         | green-500  | green-800  |
| Warning   | amber-50      | amber-500         | amber-500  | amber-800  |
| Error     | red-50        | red-500           | red-500    | red-800    |

### 2.4 Banner Anatomy

```
┌────────────────────────────────────────────────────────────┐
│ [3px color border] │ [icon]  Message text   [Action]    ✕  │
└────────────────────────────────────────────────────────────┘
```

| Element       | Specs                                              |
| ------------- | -------------------------------------------------- |
| Left border   | 3px, semantic color                                |
| Icon          | 18-20px, semantic color, left of text, 8px gap     |
| Message       | 14px, font-normal, semantic-dark (e.g., blue-800)  |
| Action        | 13px, font-medium, inline link/button              |
| Close         | 16px, neutral-400, rightmost, hover:neutral-600    |
| Height        | 44-56px (single line), auto (multi-line)           |
| Padding       | 12px 16px                                          |

### 2.5 Dismiss Behavior

Banners are **persistent until dismissed** (unlike toasts which auto-dismiss). The user must actively close them via the ✕ button. Dismissal should be remembered (via cookie or session) so the same banner does not reappear on page reload.

### 2.6 Multi-Line Banners

When the message exceeds one line:
```
┌──────────────────────────────────────────────────────────────┐
│ ⚠️  We detected unusual activity on your account. Please      │
│    review your recent login history and change your password  │
│    if anything looks suspicious.              [Review]     ✕  │
└──────────────────────────────────────────────────────────────┘
```

Text wraps naturally. Action button stays vertically centered. Close button stays top-right aligned.

## 3. Dialog / Modal

### 3.1 Visual Specification

```
┌─────────────────────────────────────────────────┐
│  ┌─────────────────────────────────────────┐    │
│  │  Dialog Title                       ✕   │    │  ← header
│  │  ────────────────────────────────────   │    │
│  │                                         │    │  ← body
│  │  Are you sure you want to delete this   │    │
│  │  project? This action cannot be undone. │    │
│  │  All associated tasks and files will    │    │
│  │  be permanently removed.                │    │
│  │                                         │    │
│  │  ────────────────────────────────────   │    │
│  │              [Cancel]  [Delete Project] │    │  ← footer
│  └─────────────────────────────────────────┘    │
│                                                 │
│  ← overlay (black/40-50 opacity, fixed)        │
└─────────────────────────────────────────────────┘
```

### 3.2 Overlay / Backdrop

| Property       | Value                                    |
| -------------- | ---------------------------------------- |
| Background     | rgba(0, 0, 0, 0.4) to rgba(0, 0, 0, 0.5)|
| Position       | fixed, inset: 0                          |
| Z-index        | 80 (above sidebar and topbar)            |
| Animation      | fade in 200ms ease-out                   |
| Click behavior | closes dialog (configurable, disable for mandatory actions) |

### 3.3 Size Variants

| Size    | Max Width | Use Case                                      |
| ------- | --------- | --------------------------------------------- |
| sm      | 400px     | Simple confirmations, alerts, short forms     |
| md      | 560px     | Standard dialogs, multi-field forms           |
| lg      | 720px     | Complex forms, detail views, settings panels  |
| xl      | 960px     | Full-featured panels, multi-step flows        |
| full    | 100vw-32px| Very complex workflows, image galleries       |

Dialog height: auto (min-content) with max-height of 85vh. When content exceeds max-height, the body area scrolls.

### 3.4 Header

```
┌──────────────────────────────────────────┐
│  [icon?]  Dialog Title              ✕    │
└──────────────────────────────────────────┘
```

| Element       | Specs                                          |
| ------------- | ---------------------------------------------- |
| Title         | 18px, font-semibold, text-primary              |
| Optional icon | 20px, left of title, semantic                  |
| Close button  | 32px hit area, 16px ✕ icon, neutral-400        |
| Padding       | 20px 24px                                      |
| Bottom border | 1px solid neutral-100 (optional, for separation)|

### 3.5 Body

| Property       | Value                                    |
| -------------- | ---------------------------------------- |
| Padding        | 24px                                     |
| Font size      | 14px                                     |
| Text color     | text-primary for content, text-muted for description |
| Max height     | calc(85vh - header - footer)             |
| Overflow       | auto (scroll when needed)                |

### 3.6 Footer

```
┌──────────────────────────────────────────────────┐
│            [Cancel]    [Delete Project]          │
│             ↑                      ↑             │
│     secondary/neutral     primary/destructive    │
└──────────────────────────────────────────────────┘
```

Layout rules:
- Buttons are **right-aligned**
- Cancel is left of the primary action (not the other way around)
- Gap between buttons: 12px
- Padding: 16px 24px
- Top border: 1px solid neutral-100 (optional, for separation)
- Mobile: buttons stack full-width (primary on top, cancel below)

Button styling:
- Cancel: ghost or outline button (transparent bg, neutral-300 border, neutral-700 text)
- Primary: solid button (accent-500 bg, white text)
- Destructive: solid button (danger-500 bg, white text) — only for delete/unrecoverable actions
- Both buttons: same height (40px), same font size (14px)

### 3.7 Keyboard Behavior

| Key        | Action                                            |
| ---------- | ------------------------------------------------- |
| Escape     | Close dialog (unless `closeOnEscape` is false)    |
| Tab        | Trapped within dialog (cycle through focusable elements) |
| Shift+Tab  | Cycle backward through focusable elements         |
| Enter      | Activate default action (if focus is not on Cancel)|

On open:
- Focus the **first focusable element** (or the primary CTA if it's a confirmation)
- Never focus the close button first (that makes accidental dismissal too easy)
- Trap focus: Tab from last element wraps to first, Shift+Tab from first wraps to last

### 3.8 Animation

Entry:
```
Backdrop: fade in, opacity 0 → 1, 200ms ease-out
Dialog:   fade in + scale(0.95) → scale(1), opacity 0 → 1, 200ms ease-out
```

Exit:
```
Backdrop: fade out, opacity 1 → 0, 150ms ease-in
Dialog:   fade out + scale(1) → scale(0.95), opacity 1 → 0, 150ms ease-in
```

The subtle scale-up (0.95→1) adds polish without being ostentatious. Never bounce — it cheapens the UI.

## 4. Loading Indicators

### 4.1 Spinner

```
◌   (16-24px, accent-500, rotating 360° every 600ms, linear)
```

| Property       | Value                                    |
| -------------- | ---------------------------------------- |
| Size           | 16-24px (use 20px default)               |
| Color          | accent-500 (brand)                       |
| Stroke width   | 2-3px                                    |
| Track color    | accent-500 at 25% opacity (visible trail)|
| Animation      | spin 600ms linear infinite               |
| Use threshold  | operations taking >300ms                 |

**Critical: never show a spinner for operations under 300ms.** Spinners that flash briefly confuse users (they glimpse it but can't process what happened). Use an optimistic UI or a debounced loading state.

Inline spinner example (inside a button):
```
[◌  Saving...]     ← spinner 16px, text 14px, gap 8px
```

### 4.2 Skeleton Screen

```
┌──────────────────────────────────────────────┐
│  ┌────────────────┐                          │  ← skeleton block (text line)
│  └────────────────┘                          │
│  ┌──────────────────────────┐                │
│  └──────────────────────────┘                │
│  ┌─────────────────────┐                     │
│  └─────────────────────┘                     │
│                                              │
│  ┌──────────┐  ┌──────────┐                 │  ← skeleton cards
│  │          │  │          │                 │
│  │          │  │          │                 │
│  └──────────┘  └──────────┘                 │
└──────────────────────────────────────────────┘
```

Skeleton rules:
- Shape: match the layout of the content that will appear
- Background: neutral-100 or neutral-200 (never a color)
- Animation: pulse (opacity alternates 1.0 ↔ 0.5, 1.5s infinite) OR shimmer (gradient sweep)
- No actual text (use rounded bars of varying widths: 40%, 70%, 60%)
- Rows: 3-5 skeleton rows for text, proportional to expected content length
- Images: rounded rectangle blocks, neutral-200, icon placeholder in center (optional)

Skeleton preference over spinner:
- Page loads: always use skeleton (the structure is known)
- Content area loads: use skeleton
- Button action results: use spinner (the structure is NOT known)

### 4.3 Progress Bar (Determinate)

```
┌────────────────────────────────────────────────┐
│  Uploading 3 of 12 files...              25%   │
│  ████████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░   │
│  └──────┘                                      │
│   fill: accent-500, width: 25%                 │
└────────────────────────────────────────────────┘
```

Specs:
- Track: 100% width, 8-12px height, neutral-100 background, rounded-full
- Fill: accent-500, height matches track, rounded-full, width: X%
- Animation: width transition 400ms ease-out (smooth step movement)
- Label: 13px, text-muted, above bar
- Percentage: right-aligned with label, 13px, font-medium

### 4.4 Progress Bar (Indeterminate)

```
████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░  →  ████ sliding right
```

- Fill width: 30-40% of track
- Animation: fill slides from left edge to right edge, 1.5s infinite
- Easing: ease-in-out
- Use for: operations with unknown duration (server processing, waiting for response)

### 4.5 Full-Page Loading

```
┌──────────────────────┬────────────────────────────┐
│  Topbar / Sidebar     │                            │
│  (visible, functional)│    ◌                        │
│                       │    Loading your dashboard... │
│                       │                            │
└──────────────────────┴────────────────────────────┘
```

**Critical: never show a completely blank loading screen.** Even during auth checks or initial data fetches, show the app shell (topbar, sidebar) so the user knows the context. The loading indicator fills only the content area.

## 5. Empty States

### 5.1 First-Use Empty State

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│                                                     │
│                 ┌─────────────┐                     │
│                 │             │                     │
│                 │ Illustration│                     │  ← 200×200px
│                 │  (neutral)  │                     │
│                 │             │                     │
│                 └─────────────┘                     │
│                                                     │
│           Welcome to Your Dashboard                  │  ← heading: 18-20px, font-semibold
│                                                     │
│     Connect your accounts and invite your team       │  ← description: 14px, text-muted
│     to get started. It only takes 2 minutes.         │     max 2 lines, max 400px width
│                                                     │
│              [ Get Started → ]                       │  ← single primary CTA
│                                                     │
│          Learn more about features →                 │  ← optional secondary link
│                                                     │
└─────────────────────────────────────────────────────┘
```

Layout rules:
- Entire block: centered horizontally and vertically in the content area
- Max width of text block: 400px
- Max width of illustration: 200px
- Gap between illustration and heading: 24px
- Gap between heading and description: 8px
- Gap between description and CTA: 24px
- Padding around the entire block: 48px top and bottom

### 5.2 No-Results Empty State

```
┌──────────────────────────────────────────────┐
│                                              │
│                 🔍 (40px icon)               │
│                                              │
│        No results for "asdfghjkl"            │  ← heading: 16px, font-medium
│                                              │
│      Try adjusting your search terms or      │  ← description: 14px, text-muted
│      removing filters to find what you       │
│      are looking for.                        │
│                                              │
│           [ Clear Filters ]                  │  ← action button
│                                              │
└──────────────────────────────────────────────┘
```

Critical: always echo the user's query back to them. "No results" is vague; "No results for 'asdfghjkl'" is informative.

### 5.3 No-Data Empty State

```
┌──────────────────────────────────────────────┐
│                                              │
│              📋 (40px icon)                  │
│                                              │
│         No projects yet                      │  ← heading: 16px, font-medium
│                                              │
│      Create your first project to start      │  ← description: 14px, text-muted
│      tracking tasks and collaborating        │
│      with your team.                         │
│                                              │
│         [ Create Project ]                   │  ← CTA to create/add first item
│                                              │
└──────────────────────────────────────────────┘
```

This is distinct from "no-results." No-data means the collection is genuinely empty (new user, no items created). The CTA should lead to the creation flow.

### 5.4 Empty State Icon Specs

- Icon size: 40-48px for simple icons, 120-200px for full illustrations
- Icon color: neutral-300 (muted, does not compete with text)
- Never use an error icon (red ✕) for empty states — it implies something broke

## 6. Error States

### 6.1 Inline Field Error

(Detailed in forms.md §3. Error Message Format.)

### 6.2 Banner Error

```
┌──────────────────────────────────────────────────────────────┐
│ ❌  Failed to save changes. The server is currently           │
│    unavailable. Please try again in a few minutes.  [Retry]  ✕│
└──────────────────────────────────────────────────────────────┘
```

Use for: recoverable errors at the section or page level (failed API call, sync error, permission denied on a specific action).

### 6.3 Toast Error

```
┌────────────────────────────────────────┐
│ ✕  Message failed to send              │
│    Check your connection and try again.  │
│                               Retry  ✕  │
└────────────────────────────────────────┘
```

Use for: non-blocking operation failures (send message, like item, auto-save). The user can continue working; the error is informative, not blocking.

### 6.4 Full-Page Error

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│                                                     │
│                 ┌─────────────┐                     │
│                 │    ⚠️       │                     │  ← 48-64px icon, amber-400
│                 └─────────────┘                     │
│                                                     │
│           Something went wrong                      │  ← heading: 20-24px, font-semibold
│                                                     │
│     We're having trouble loading this page.          │  ← description: 14px, text-muted
│     Our team has been notified and is working        │
│     on a fix.                                       │
│                                                     │
│         [ Try Again ]    [ Go Home ]                │  ← two actions
│                                                     │
│          Error code: ERR_FETCH_FAILED               │  ← 12px, text-muted (for support)
│                                                     │
└─────────────────────────────────────────────────────┘
```

Use for: unrecoverable page-level errors (failed to load critical data, 500 server errors). Always include:
1. Human-readable explanation (no stack traces to users)
2. Retry action
3. Escape hatch (Go Home / Go Back)
4. Error code or reference ID (for support)

### 6.5 404 Page

```
┌─────────────────────────────────────────────────────┐
│                                                     │
│                   404                                │  ← display size, neutral-200
│                                                     │
│              Page not found                          │  ← 20-24px, font-semibold
│                                                     │
│      The page you're looking for doesn't exist       │  ← 14px, text-muted
│      or has been moved.                              │
│                                                     │
│              [Search...           ]                  │  ← search bar (optional but recommended)
│                                                     │
│              [ Go to Home ]                          │  ← primary CTA
│                                                     │
└─────────────────────────────────────────────────────┘
```

Always include a search bar (if the app has search) and a home link.

## 7. Success States

### 7.1 Toast Confirmation

Default success feedback pattern. See §1 (Toast) for full specs.

### 7.2 Inline Success

After form submission, replace the form with:
```
┌──────────────────────────────────────────────┐
│                                              │
│           ✓ (48px, green-500)                │
│                                              │
│       Your profile has been updated           │  ← 16px, font-medium
│                                              │
│       [Go to Profile] [Make another change]  │
│                                              │
└──────────────────────────────────────────────┘
```

Use for: short forms where the user needs confirmation that the action completed. Not suitable for multi-step forms (use a redirect instead).

### 7.3 Redirect with Banner

After creating a resource (e.g., new project), redirect to the resource's page with a success banner:
```
┌──────────────────────────────────────────────────────────────┐
│ ✓  Project "Alpha" created successfully.  [View Project]    ✕│
└──────────────────────────────────────────────────────────────┘
```

The banner auto-dismisses after 5 seconds, same as a toast, but is full-width to integrate with the page layout.

## 8. Confirmation Dialogs

### 8.1 Destructive Confirmation

For irreversible or dangerous actions (delete, archive, remove permissions):

```
┌──────────────────────────────────────────────┐
│                                              │
│  Delete Project?                             │  ← title: 18px, font-semibold
│                                              │
│  Are you sure you want to delete "Project    │  ← body: 14px
│  Alpha"? This action cannot be undone. All   │
│  tasks, files, and comments will be          │  ← clearly describe consequences
│  permanently removed.                        │
│                                              │
│  This project has 42 tasks and 3 members.    │  ← additional context
│                                              │
│            [Cancel]    [Delete Project]      │  ← destructive action uses danger-500
│                ↑              ↑              │     Cancel is default focus
│          default focus   danger-500 bg       │
└──────────────────────────────────────────────┘
```

Critical rules for destructive confirmations:
1. The destructive action button uses **danger-500** background (red)
2. The cancel button is the **default focus** (prevents accidental Enter = delete)
3. The title clearly states the action + subject ("Delete Project?")
4. The body describes **specific consequences** ("42 tasks and 3 members will be removed")
5. Never make the destructive action the default/primary focus position

### 8.2 Standard Confirmation

For non-destructive confirmations (save before leaving, publish, send):

```
┌──────────────────────────────────────────────┐
│                                              │
│  Save Changes?                               │
│                                              │
│  You have unsaved changes. Would you like    │
│  to save them before leaving?                │
│                                              │
│     [Don't Save]    [Cancel]    [Save]       │
│        ↑               ↑          ↑          │
│      ghost          ghost     accent-500     │
└──────────────────────────────────────────────┘
```

Three-button layout for save-before-leaving dialogs. The primary save action is rightmost and has accent-500 styling.

### 8.3 Confirmation Without Dialog

For low-stakes actions, prefer inline confirmation over a dialog:

```
┌──────────────────────────────────┐
│  Archive this project?           │
│  [Archive]  [Cancel]             │
└──────────────────────────────────┘
     ↑ inline within the page, not a modal

After clicking Archive:
┌──────────────────────────────────┐
│  ✓ Project archived.  [Undo]     │
└──────────────────────────────────┘
```

Dialogs interrupt flow. Reserve them for truly consequential actions.

## 9. Anti-Slop Rules for Feedback

The following patterns are **forbidden**:

1. **Silent failures** — Every error must be communicated to the user. A failed API call with no visual feedback is the worst possible UX. Silent failures erode trust permanently.
2. **Loading spinners for sub-300ms operations** — Spinners that appear and disappear in under 300ms are visual noise. Use a debounced loading state (start showing after 300ms).
3. **Blank loading screens** — Even during auth checks or heavy data fetching, show the app shell (topbar, sidebar). A blank white screen signals a crash, not loading.
4. **Un-dismissible toasts** — Every toast must have a close button AND auto-dismiss. A toast that covers content indefinitely without a way to close it is a permanent obstruction.
5. **Toast overload** — Never show more than 3 toasts simultaneously. Queue or dismiss older ones. A stack of 5 toasts is a wall of noise.
6. **Technical error messages** — Never show "TypeError: Cannot read property 'name' of undefined" to users. Translate every error into human-readable language. Include error codes for debugging, not raw stack traces.
7. **"Are you sure?" with no specifics** — A confirmation that says only "Are you sure?" provides no information. Always specify what will happen and what the consequences are.
8. **Missing close button on dialogs** — Every dialog must be closable via ✕ button AND Escape key AND backdrop click (except mandatory-acknowledgment dialogs).
9. **Success toasts for trivial actions** — "Settings saved" for every toggle is excessive. Use optimistic UI for trivial changes. Reserve toasts for multi-field form submissions and consequential actions.
10. **Empty states with zero action** — An empty state that says "No items" with no button to add items is a dead end. Always provide a path forward.

## 10. Summary — Feedback Decision Matrix

| Situation                                | Component              | Notes                                     |
| ---------------------------------------- | ---------------------- | ----------------------------------------- |
| Operation succeeded (non-blocking)       | Toast (success)        | Auto-dismiss 5s, top-right, with undo     |
| Operation succeeded (after form submit)  | Inline success or redirect | Replace form or navigate away         |
| Operation failed (non-blocking)          | Toast (error)          | Auto-dismiss 7s, with Retry button        |
| Operation failed (section-level)         | Banner (error)         | Persistent until dismissed, with Retry    |
| Operation failed (page-level)            | Full-page error        | Explanation + Retry + Home link           |
| Delete / destructive action              | Dialog (destructive)   | Danger button, Cancel is default focus    |
| Save before leaving                      | Dialog (standard)      | Save / Don't Save / Cancel                |
| Page loading                             | Skeleton screen        | Match layout shape, pulse animation       |
| Operation in progress (>300ms)           | Spinner                | Inside button or centered in area         |
| Operation in progress (known duration)   | Progress bar           | Determinate, with percentage              |
| First use, no items                      | Empty state (first-use)| Illustration + heading + CTA             |
| Search returned nothing                  | Empty state (no-result)| Echo query, suggest action, clear filters |
| Collection is empty                      | Empty state (no-data)  | Contextual message + creation CTA         |
| Page not found                           | 404 page               | Friendly message + search + home link     |
| Unsaved changes warning                  | Dialog (standard)      | Three-button pattern                      |
| Info that needs user's attention         | Banner (info)          | Persistent, full-width, below topbar      |
